Pa Architecture & Specification

Inspired by Python, 100% Python-syntax compatible. Written by AI, auditable by humans. Pa (.pa) compiles clean, zero-annotation Python syntax into contiguous C++-style memory with deterministic RAII, zero GC, and LLVM machine code — while reaching the Python ecosystem through typed, checked, replayable .paw modules.

01

Design principles

1. Python syntax, zero type noise

Every .pa file parses with ast.parse. Function bodies carry no type noise; types come from bidirectional inference.

2. Contiguous memory, RAII

Lists compile to flat arrays ([N x T], {T*, len, cap}), never PyObject* arrays. Heap memory is freed at scope exit with zero GC.

3. Host-first architecture

Pa owns main(), control flow, and compute. Python libraries live behind a locked boundary as a sandboxed toolbox.

4. First-class boundary customs

Every crossing is typed, checked in both directions, and replayable from a JSON fault snapshot — no silent corruption.

5. AI-native diagnostics

pac check --ai-diagnostic emits self-contained JSON repair tickets with causal chains and deterministic patches.

6. Safe by default, lean on demand

--mode dev bounds-checks and deep-lints; --mode prod removes runtime checks for C++/LLVM-class throughput.

02

Source files & the two-zone architecture

SuffixZoneRules & Role
*.pa Native zone (LLVM) 100% compiled to native machine code. May import only pa, pa_lang, and project-local .paw modules (PA_E001 otherwise).
*.paw Crossing zone (CPython) Standard Python (NumPy, Pandas, PIL, requests, …). Every public function requires a locked static In -> Out signature acting like a C header.
*.py Thin shell (optional) For frameworks owning the event loop (FastAPI, Flask, Streamlit). Calls @export functions in a compiled .so; holds no business logic.
Host-First & Batching rule: .paw modules are stateless adapters — dynamic objects (DataFrame, PIL Image, HTTP Response) are created and consumed inside .paw; only scalars, strings, and flat numeric buffers cross. Calling a .paw function inside any loop is a compile error (PA_E002): pack inputs on the Pa side and cross once.
Framework-driven apps: Compile @export entry points with pac build lib.pa --shared -o lib.so. Calls are guarded by setjmp so faults return an error code via pa_error_code() without crashing the host process.

05

Memory model

Assignment copies

b = a deep-copies arrays, structs, and vecs (llvm.memcpy; stack copies > 4 KB warn PA_W001). Raw pointer aliasing is forbidden (PA_E070).

Calls borrow

Containers and structs pass as zero-copy read-only borrows. Mutating callees require explicit mut(x) at the call site (PA_E050).

No mut() aliasing

Passing the same container twice when one is mut() is rejected (PA_E089). Scalar reads like f(mut(v), v[i]) load by value first and are allowed.

Storage TierConditionCompiled Representation
Tier 1 · Stack Scalars, structs, constant lists (≤ 64 KB), or non-escaping dynamic lists with a known constant append bound [N x T] or stack-backed StackVec: zero malloc, O(1) stack pointer release.
Tier 2 · Heap RAII Unbounded appends, runtime [x] * n, escapes via return, or > 64 KB Vec[T] (cap starts at 16 and doubles); compiler inserts free on every exit path unless returned.
Tier 3 · Hard Error Heterogeneous list (PA_E030), uninferable [] (PA_E011), escaping span (PA_E040), alloc leak/UAF (PA_E004) Compilation stops with a structured repair ticket.

Strings: UTF-8 bytes (len("héllo") == 6, s[i] is u8). Concatenation (a + b, s += x) allocates an RAII-owned String; temporary strings must be bound to a local (PA_E072) so RAII owns and frees them.

07

The .paw boundary

When infer.py sees import x and x.paw exists, it reads only the public function signatures as a static header. At codegen time, each call emits a marshaling stub into pa_call_paw() in runtime_bridge.c:

  • Allowed boundary types: parameters accept i32 i64 u8 u32 u64 f32 f64 bool (plus int/float), str_view, span[T], list[T, N], and Vec[T]. Returns accept numeric scalars, Vec[T], or void (never a string — return Vec[u8]).
  • Zero-copy buffers: contiguous Pa arrays (FixedList, Vec, StackVec, Span) are exposed to Python via read-only PyMemoryView_FromMemory cast to the native format (i/q/B/I/Q/f/d/?), so np.frombuffer(arr, …) reads Pa memory directly.
  • Two-way customs: out-bound (PA_TO_PY_IN) checks NaN/Inf (waivable per-function via @allow_nan), NULL pointers, negative lengths, and narrowing ranges; in-bound (PY_TO_PA_OUT) rejects None, NaN/Inf, type drift, integer overflow, buffer format mismatch, and Python exceptions. Every violation writes a replayable in_payload_snapshot.
  • Embedded & relocatable: imported .paw sources are embedded into the binary (runtime __file__ is <embedded>/<name>.paw; override with PA_PATH). Pure-native binaries with no .paw link no Python at all.

13

Platform support, limits & roadmap

Current limits (v0.1.0)
  • Linux x86-64, macOS (arm64 / x86-64), and Windows x64 build targets.
  • .paw cannot return strings or structs; @struct fields cannot be Vec yet.
  • Helpers are monomorphic over container layouts (do not mix stack FixedList and heap Vec at the same parameter).
  • No dict/set/tuple, closures, generators, or try/except.
Roadmap & Non-goals
  • Standalone ecosystem packages (pa-libs) built on multi-file .pa module imports (-I / PA_PATH / pip packages).
  • (Low priority) Nested Vec fields inside @struct with recursive RAII destructors (flat SoA arrays and CSR Vec[Vec[T]] are preferred).
  • Non-goal: static libpython single-file binaries (incompatible with Windows/macOS CPython distributions and third-party .pyd/.so C extensions; use pac build --bundle --with-stdlib instead).
